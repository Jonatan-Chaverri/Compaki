# Idiomas de la aplicación web

La interfaz usa `next-intl` con el App Router. Las rutas se mantienen iguales en ambos idiomas.

- Español: `apps/web/messages/es.json`
- Inglés: `apps/web/messages/en.json`
- Configuración por solicitud: `apps/web/src/i18n/request.ts`
- Selector del menú: `apps/web/src/components/language-menu.tsx`

El idioma elegido se guarda durante un año en la cookie `compaki-locale`. Sin preferencia guardada, se usa el primer idioma compatible de `Accept-Language`; si no hay ninguno, se muestra español. El atributo `lang` del documento y los metadatos siguen esta preferencia.

En componentes síncronos y de cliente:

```tsx
const t = useTranslations("ui");
return <button>{t("saveChanges")}</button>;
```

En páginas y funciones asíncronas del servidor:

```tsx
const t = await getTranslations("ui");
```

Agrega cada mensaje con la misma clave en ambos catálogos. Usa variables ICU y mensajes plurales completos, por ejemplo `t("productCount", {count})`; evita concatenar sufijos o traducir identificadores persistidos. Pasa el idioma de `useLocale()` o `getLocale()` a los helpers de importes y fechas.

Los nombres, descripciones y relatos escritos por vendedores u organizadores se conservan tal como fueron publicados. Las categorías internas, estados, direcciones de cuentas y códigos de moneda conservan sus valores; sus etiquetas de interfaz se traducen por separado. Los mensajes de servicios externos se convierten a mensajes locales conocidos o a una explicación genérica traducida. Las ventanas alojadas por proveedores externos conservan los idiomas que esos proveedores admiten.

El cambio de idioma actualiza componentes del servidor y del cliente sin modificar la URL ni reiniciar los formularios. Las pruebas comprueban la elección de idioma, la correspondencia de claves, la sintaxis ICU, las variables utilizadas y los plurales:

```sh
cd apps/web
node --test tests/*.test.mjs
npm run typecheck
npm run lint
npm run build
```
